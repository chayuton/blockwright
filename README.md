# Blockwright

**เรียง · ต่อ · ก่อ** — เครื่องมือสร้างเกมด้วยการต่อบล็อก ใช้ภาษาไทยทั้งหมด

คำว่า *wright* แปลว่าช่างผู้สร้าง อยู่ตระกูลเดียวกับ shipwright และ playwright Blockwright จึงหมายถึงช่างผู้ก่อสิ่งต่าง ๆ ขึ้นจากบล็อก

ลากบล็อกมาต่อกันทางซ้าย กดเล่นแล้วเห็นผลทางขวาทันที ไม่ต้องคอมไพล์ ไม่ต้องรีเฟรช บล็อกทุกตัวแปลงเป็น JavaScript จริงที่เปิดดูได้ และส่งออกเป็นไฟล์ HTML ที่เล่นได้เดี่ยว ๆ

---

## สิ่งที่มีอยู่ในกล่อง

- **บล็อกภาษาไทย 57 ตัว** แบ่ง 7 หมวด — เริ่มเกม, ตัวละคร, การควบคุม, เวลา, การชน, คะแนนและเสียง, จบเกม บวกหมวดตรรกะ ทำซ้ำ ตัวเลข ข้อความ ตัวแปร และฟังก์ชันของ Blockly เอง
- **เอนจินเกมเขียนขึ้นเอง** ลูปคงที่ 60 เฟรมต่อวินาที, การชนแบบกล่องสี่เหลี่ยม, การยืนบนพื้นและกระโดด, โหมดขอบเวที 5 แบบ, ตัวจับเวลา, แถบคะแนน และเสียงสังเคราะห์จาก WebAudio
- **เกมตัวอย่าง 6 แนว** แพลตฟอร์ม, ยานอวกาศยิงศัตรู, เก็บของแข่งกับเวลา, ทุบอิฐ, คลิกเป้า, เอาตัวรอดเล็งด้วยเมาส์ ทั้งหกใช้ชุดบล็อกเดียวกันหมด ต่างกันแค่วิธีต่อ
- **ชื่อตัวละครเป็นรายการให้เลือก** สะกดผิดไม่ได้ และเปลี่ยนชื่อทีเดียวแก้ให้ทุกบล็อกที่ใช้
- **ป้ายในรายการเลือกเขียนไทยควบอังกฤษ** เช่น `เด้งกลับ · Bounce` และ `ความเร็วแนวนอน · vx` ผู้เรียนจึงเห็นศัพท์ที่ใช้จริงในวงการไปพร้อมกัน ส่วนค่าที่เก็บจริงไม่เปลี่ยน โปรเจกต์เก่าโหลดได้ตามปกติ
- **ส่งออกเป็นไฟล์เกมเดี่ยว** คัดลอกเป็น HTML ไฟล์เดียวที่เปิดเล่นได้โดยไม่ต้องพึ่งหน้านี้
- **ชุดทดสอบที่ไม่ต้องเปิดเบราว์เซอร์** เล่นเกมตัวอย่างทั้งหกด้วยนักบินอัตโนมัติ แล้วตรวจว่าทำคะแนนได้จริง

ทั้งหมดเป็นเว็บสแตติกล้วน ไม่มีขั้นตอน build ไม่มีเซิร์ฟเวอร์ ไม่มีฐานข้อมูล

## ดีพลอยบน Vercel

เป็นเว็บสแตติกล้วน จึง **ไม่ต้องมีขั้นตอน build**

### ทางที่ 1 — ผ่านหน้าเว็บ Vercel

1. เข้า [vercel.com/new](https://vercel.com/new) แล้วเลือก **Import Git Repository** ชี้ไปที่รีโปที่เพิ่ง push
2. ในหน้า Configure Project ตั้งค่าดังนี้
   - **Framework Preset** → `Other`
   - **Build Command** → เว้นว่าง (ปิดสวิตช์ Override ไว้)
   - **Output Directory** → เว้นว่าง หรือใส่ `.`
   - **Root Directory** → `./`
3. กด **Deploy** รอไม่ถึงนาทีก็ได้ลิงก์

หลังจากนั้นทุกครั้งที่ push ขึ้น `main` Vercel จะดีพลอยให้เอง ส่วน pull request จะได้ลิงก์พรีวิวแยกของตัวเอง

### ทางที่ 2 — ผ่าน CLI

```bash
npm i -g vercel
vercel          # ดีพลอยเป็นพรีวิว ตอบคำถามตามค่าเริ่มต้นได้เลย
vercel --prod   # ดีพลอยขึ้นโดเมนจริง
```

### ไฟล์ vercel.json

ไฟล์ `vercel.json` ในรีโปตั้งค่าไว้สองอย่างเท่านั้น คือส่วนหัวความปลอดภัยพื้นฐาน และให้ไฟล์ใน `vendor/` ถูกแคชยาว ๆ เพราะไม่เปลี่ยนแปลง ไม่ได้ตั้ง build command ไว้ ตัวดีพลอยจึงเป็นการอัปโหลดไฟล์ตรง ๆ

ไฟล์ใน `src/` เป็นสคริปต์ธรรมดา ไม่ใช่ ES module แต่ละไฟล์ห่อตัวเองไว้ใน IIFE แล้วฝากของที่ไฟล์อื่นต้องใช้ไว้ในอ็อบเจกต์เดียวชื่อ `window.Blockwright` ลำดับการโหลดจึงสำคัญ และเป็นลำดับเดียวกับที่เขียนไว้ใน `index.html`

```

generators.js  รับ C · ส่งออก JS (ตัวแปลง) และ TOOLBOX
engine.js      ส่งออก createEngine
templates.js   ส่งออก TEMPLATES
app.js         รับทั้งสี่ตัวข้างบนมาประกอบเป็นหน้าจอ
```

## บล็อกหนึ่งตัวกลายเป็นเกมได้อย่างไร

```
ผู้ใช้ลากบล็อก
      ↓
Blockly serialization  ── บันทึกลง localStorage และช่องโปรเจกต์
      ↓
javascriptGenerator    ── แปลงเป็นข้อความ JavaScript ที่เรียก API ตัวเดียวชื่อ G
      ↓
new Function('G', โค้ด) ── เรียกครั้งเดียวเพื่อลงทะเบียนตัวจัดการเหตุการณ์
      ↓
เอนจิน                 ── เดินลูป 60 fps เรียกตัวจัดการ คำนวณฟิสิกส์ วาดลง canvas
```

บล็อกทุกตัวแปลงออกมาเป็นการเรียกเมท็อดของ `G` เท่านั้น เช่นบล็อกสร้างตัวละครกลายเป็น

```js
G.create("ผู้เล่น", "🧍", 32, 60, 300);
```

เอนจินจึงเป็นอิสระจาก Blockly อย่างสมบูรณ์ `createEngine` ไม่อ้างถึงตัวแปรภายนอกเลยแม้แต่ตัวเดียว เพราะเหตุนี้ปุ่มส่งออกจึงทำงานได้ด้วยการเรียก `createEngine.toString()` แล้วแปะต่อกับโค้ดของเกม

## เพิ่มบล็อกใหม่

สมมติอยากได้บล็อก **ย่อขยาย [ตัวละคร] เป็น [n] เท่า** ต้องแตะสามไฟล์

**1. `src/blocks.js`** เพิ่มเข้าไปในอาร์เรย์ชุดที่สาม ฟังก์ชัน `SPR()` ช่วยสร้างช่องเลือกชื่อตัวละครให้

```js
{ type:'sprite_scale', message0:'ย่อขยาย %1 เป็น %2 เท่า',
  args0:[SPR('NAME'), {type:'input_value', name:'K', check:'Number'}],
  inputsInline:true, previousStatement:null, nextStatement:null, colour:C.sprite,
  tooltip:'1 คือขนาดเดิม 2 คือใหญ่ขึ้นเท่าตัว' },
```

**2. `src/generators.js`** เพิ่มตัวแปลง แล้วใส่บล็อกลงกล่องเครื่องมือ

```js
gen('sprite_scale', function(b,g){
  return 'G.scale(' + SN(b,'NAME') + ',' + V(b,g,'K','1') + ');\n'; });
```

```js
// ในหมวด 🧍 ตัวละคร ของ TOOLBOX
tb('sprite_scale', {K:1.5}),
```

**3. `src/engine.js`** เพิ่มเมท็อดลงในอ็อบเจกต์ `G`

```js
scale:function(name, k){
  var f = Math.max(0.05, num(k, 1));
  list(name).forEach(function(e){ e.w = e.w * f; e.h = e.h * f; });
},
```

เสร็จแล้วรีเฟรชหน้าเว็บ บล็อกใหม่จะอยู่ในกล่องเครื่องมือทันที ไม่ต้อง build

ตัวช่วยที่ใช้บ่อยในไฟล์ generators คือ `SN(b,'NAME')` อ่านชื่อตัวละครออกมาเป็นข้อความ `V(b,g,'ช่อง','ค่าเริ่มต้น')` อ่านค่าจากช่องเสียบ `F(b,'ช่อง')` อ่านค่าจากรายการเลือก และ `ST(b,g,'DO')` อ่านบล็อกที่วางซ้อนอยู่ข้างใน

## เพิ่มเกมตัวอย่าง

เกมตัวอย่างอยู่ใน `src/templates.js` เขียนด้วยฟังก์ชันช่วยสั้น ๆ แทนการเขียน JSON ดิบ

```js
'myGame': { label:'🎈 ชื่อที่จะขึ้นในเมนู', build:function(){ return doc([
  at(SETUP([
    B('game_background', { COL:'#a8dcf5' }),
    B('sprite_create', { NAME:'ผู้เล่น', LOOK:'🧍', SIZE:32 }, { X:N(240), Y:N(180) })
  ]), 24, 24),
  at(TICK([ B('ctrl_move', { NAME:'ผู้เล่น', MODE:'arrows' }, { SPD:N(200) }) ]), 24, 400)
]); }},
```

ชื่อตัวละครเขียนเป็นข้อความธรรมดาได้เลย ฟังก์ชัน `markVars()` จะเดินทั้งต้นไม้บล็อกแล้วแปลงเป็นการอ้างตัวแปรชนิด `Sprite` พร้อมสร้างรายการ `variables` ให้เอง ตัวเลข `at(block, x, y)` คือตำแหน่งที่บล็อกจะไปวางบนลานต่อบล็อก

ถ้าเพิ่มบล็อกใหม่ที่มีช่องชื่อตัวละคร อย่าลืมประกาศไว้ในตาราง `SPRITE_FIELDS` ที่หัวไฟล์เดียวกัน ไม่งั้น `markVars()` จะมองไม่เห็นช่องนั้น

เพิ่มเทมเพลตแล้วอย่าลืมเพิ่มเกณฑ์ตรวจใน `test/run.mjs` ที่ตัวแปร `EXPECT` และเขียนนักบินอัตโนมัติไว้ใน `PILOTS` ถ้าเกมต้องกดปุ่ม

## ทดสอบ

```bash
npm test
```

ชุดทดสอบรันใน Node ล้วน ไม่เปิดเบราว์เซอร์ แต่เดินครบสายของจริง คือโหลดเทมเพลตเข้า Blockly แบบ headless แปลงเป็น JavaScript ป้อนเข้าเอนจินที่มี canvas จำลอง แล้วขับ `requestAnimationFrame` เองทีละเฟรม พร้อมนักบินอัตโนมัติที่กดปุ่ม เลื่อนเมาส์ และคลิกแทนผู้เล่น

เกณฑ์ผ่านไม่ใช่แค่ไม่พัง แต่ต้อง **ทำคะแนนได้จริง** เช่นเกมแพลตฟอร์มต้องกระโดดขึ้นแท่นเก็บเหรียญได้ เกมยานอวกาศต้องยิงโดนศัตรู เกมเก็บแอปเปิลต้องเก็บครบจนชนะ และบางเกมมีเงื่อนไข `survive` บังคับว่าตัวละครบางกลุ่มต้องยังอยู่บนเวทีจนจบ

วิธีนี้จับบั๊กเชิงตรรกะที่โค้ดไม่ได้ error เลยสักบรรทัดได้สองตัวแล้ว ตัวแรกคือศัตรูที่เกิดเหนือจอถูกลบทิ้งทันทีเพราะเข้าเงื่อนไขออกนอกเวที ตัวที่สองคือพื้นและแท่นในเกมแพลตฟอร์มร่วงพ้นจอภายในครึ่งวินาทีเพราะโดนแรงโน้มถ่วงดึงเหมือนตัวละครอื่น ซึ่งแก้ด้วยบล็อก `📌 ตรึงไว้กับที่`

## เลิกพึ่ง CDN

ค่าเริ่มต้นโหลด Blockly จาก jsDelivr ถ้าต้องการให้ทำงานแบบออฟไลน์ เช่นเอาไปใช้ในห้องคอมพิวเตอร์ที่เน็ตไม่เสถียร

```bash
npm install
npm run vendor:blockly
```

แล้วแก้สอง `<script>` ใน `index.html` ให้ชี้มาที่ `vendor/blockly/blockly.min.js` และ `vendor/blockly/msg/th.js` พร้อมเอาบรรทัด `vendor/blockly/` ออกจาก `.gitignore`

แบบอักษรจาก Google Fonts ยังเหลืออยู่ ถ้าไม่มีเน็ตหน้าเว็บจะถอยไปใช้แบบอักษรของระบบ ซึ่งยังอ่านออกตามปกติ

## เรื่องที่ควรรู้ก่อนแก้

- **ชื่อตัวละครคือตัวแปรของ Blockly** ที่กำหนดชนิดเป็น `Sprite` จึงได้รายการเลือกและการเปลี่ยนชื่อพร้อมกันทุกบล็อกมาฟรี และไม่ไปปนกับหมวดตัวแปรทั่วไปซึ่งใช้ชนิดว่าง ค่าที่อยู่ในช่องคือ **รหัสตัวแปร ไม่ใช่ชื่อ** ตัวแปลงจึงต้องอ่านผ่าน `SN()` เสมอ
- **เมนูของช่องชื่อมีแค่เปลี่ยนชื่อกับลบ** Blockly ไม่มีตัวเลือกสร้างใหม่มาให้ จึงต้องมีปุ่ม ➕ ชื่อตัวละคร แยกไว้บนแถบเหนือลานบล็อก
- **Blockly 13 ตัด `workspace.createVariable` ออกแล้ว** ต้องเรียกผ่าน `workspace.getVariableMap().createVariable(ชื่อ, 'Sprite')`
- **`field_colour` ถูกย้ายออกจาก Blockly core ตั้งแต่ v11** โปรเจกต์นี้จึงใช้รายการเลือกสีแทน ถ้าอยากได้ตัวเลือกสีจริงต้องเพิ่มปลั๊กอิน `@blockly/field-colour`
- **ตัวแปลงของ Blockly ประกาศตัวแปรทุกตัวไว้บรรทัดแรก** รวมถึงชื่อตัวละครที่ไม่เคยถูกใช้เป็นตัวแปรจริง และแปลงอักษรไทยเป็นรหัสแบบ `_E0_B8_…` ฟังก์ชัน `trimDeclarations()` ใน `app.js` จึงตัดชื่อที่ไม่ถูกอ้างถึงที่ไหนเลยออก
- **แรงโน้มถ่วงดึงทุกตัวละคร** รวมถึงพื้นและแท่น ฉากที่ต้องอยู่นิ่งจึงต้องใส่บล็อก `📌 ตรึงไว้กับที่` เสมอ ตัวที่ถูกตรึงยังกำหนดความเร็วให้เคลื่อนที่เองได้ จึงทำแท่นเลื่อนได้
- **มุมหมุน 0 องศาคือชี้ไปทางขวา** และเพิ่มขึ้นตามเข็มนาฬิกา บล็อกหันหน้าและพุ่งไปข้างหน้าใช้กติกานี้ร่วมกัน ภาพอีโมจิไม่ได้หมุนตามทิศที่ตัวเองวาดไว้ ถ้าต้องการให้เห็นทิศชัด ใช้รูปสี่เหลี่ยมยาวแทนจะอ่านง่ายกว่า
- **เวทีมีขนาดคงที่ 480 × 360 จุด** โดย x เพิ่มไปทางขวา y เพิ่มลงล่าง และตำแหน่งตัวละครวัดจากจุดกึ่งกลาง ไม่ใช่มุมบนซ้าย
- **ไฟล์ใน `vendor/blockly-media/` ห้ามลบ** Blockly ขอไฟล์ `delete-icon.svg` สำหรับถังขยะ และ `dropdown-arrow.svg` สำหรับรายการเลือก ถ้าหายไปไอคอนจะว่างเปล่าโดยไม่มีข้อความผิดพลาด
